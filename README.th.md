> **ข้อปฏิเสธความรับผิดชอบ.** PiliBabel เป็นไคลเอนต์**ไม่เป็นทางการ โอเพนซอร์ส บุคคลที่สาม** ซึ่ง**ไม่มีความเกี่ยวข้อง ไม่ได้รับการรับรอง หรือไม่ได้รับการสนับสนุนจาก** bilibili / bilibili Inc. แต่อย่างใด API ทั้งหมดรวบรวมมาจาก endpoint สาธารณะอย่างเป็นทางการ; **ไม่มีการปลดล็อกหรือแคร็กเนื้อหาที่ต้องชำระเงิน** โปรดอ่านส่วน[ข้อปฏิเสธความรับผิดชอบ](#ข้อปฏิเสธความรับผิดชอบ)และ[สัญญาอนุญาต](#สัญญาอนุญาต)ฉบับเต็ม

## PiliBabel คืออะไร?

PiliBabel เป็น**fork บุคคลที่สามอิสระที่สร้างขึ้นบน [PiliNara](https://github.com/Starfallan/PiliNara)** และสืบทอดทุกสิ่งที่ PiliNara สืบทอดมา:

```
bilibili (API สาธารณะอย่างเป็นทางการ)
        ▲
   PiliPala / PiliPalaX        — โปรเจกต์ดั้งเดิม
        ▲
   PiliPlus                    — fork ที่ยังพัฒนาต่อ
        ▲
   PiliNara                    — fork ของ PiliPlus (ปรับแต่งส่วนตัว)
        ▲
   PiliBabel  ← คุณอยู่ที่นี่  — fork ของ PiliNara
```

PiliBabel คงทุกฟีเจอร์ของ PiliNara / PiliPlus ไว้ (ดู[บันทึกฟีเจอร์ที่สืบทอดมา](#บันทึกฟีเจอร์ที่สืบทอดมา-จาก-pilinara--piliplus)ใกล้ท้ายหน้า) และเพิ่ม**ความสามารถเด่นสองอย่างที่ไคลเอนต์ต้นน้ำไม่มี**:

> **การแปลอินเทอร์เฟซและเนื้อหาด้วย AI** — ทั้งแอป (ป้ายชื่อ UI, ชื่อวิดีโอ, ชื่อ UP, ความคิดเห็น, ไดนามิก, ฟีด และแม้แต่ดัมมากุสด) แสดงผลเป็นภาษาที่**คุณ**เลือก

และตั้งแต่เวอร์ชัน 1.0 ทำสิ่งนี้ได้**ทันทีที่ติดตั้ง**: โมเดลการแปลถูก**ฝังมาในตัว** bilibili เปิดซอร์สตระกูลโมเดลแปลภาษาของตัวเองคือ [Index-Translate](https://github.com/bilibili/Index-Translate) และให้บริการผ่าน endpoint สาธารณะฟรี PiliBabel ตั้งค่ามาชี้ที่ endpoint นี้ การแปลจึงทำงานทันทีที่ติดตั้งแอป — ไม่ต้องสมัคร ไม่ต้องมีคีย์ ไม่มีบิล ถ้าอยากใช้โมเดลของตัวเอง เส้นทาง API ของตัวเองก็ยังอยู่ ห่างเพียงแตะเดียว

> **เสียงหูฟังที่ซิงก์กันจริงๆ** — กับหูฟังบลูทูธหรือแบบมีสาย เสียงไม่ตามหลังภาพอีกต่อไป แอปทางการทำเรื่องนี้ได้ถูกต้อง ส่วน PiliNara และ PiliPlus ทำไม่ได้ตามค่าเริ่มต้น PiliBabel ตอนนี้ขอ **AudioTrack** จาก mpv เป็นอันดับแรก ซึ่ง*วัด*ความหน่วงของเอาต์พุตเสียงด้วยวิธีเดียวกับไคลเอนต์ทางการ แทน **OpenSL ES** ที่*ประมาณการ*ค่านี้เท่านั้น

## คุณสมบัติเด่น

- **เสียงหูฟังซิงก์สนิท.** ตัวเล่นใช้แบ็กเอนด์ **AudioTrack** ของ mpv เป็นค่าเริ่มต้น (ลำดับ `audiotrack,aaudio,opensles`) แทน **OpenSL ES** AudioTrack รายงานความหน่วงเอาต์พุตแบบ*วัดจริง* — อ่านจำนวนเฟรมที่เล่นไปแล้วและ timestamp การแสดงผลของอุปกรณ์ — ซึ่งเป็นวิธีเดียวกับที่แอปทางการของ bilibili และ `MediaSync` ของ Android เองใช้คุมภาพกับเสียงให้ไปด้วยกัน OpenSL ES ประมาณการ*เท่านั้น บนหูฟังบลูทูธจึงเกิดนาฬิกาเสียงล้ำและภาพถูกฉายก่อนเวลา จากการทดสอบ ความหน่วงแทบหายไป ปรับลำดับใหม่ได้ตลอดที่ Settings → Video → อุปกรณ์เอาต์พุตเสียง

- **AI แปล ทุกที่.** แท็บนำทาง การ์ดวิดีโอ หน้ารายละเอียด ความคิดเห็น ไดนามิก และหน้า ของฉัน / รายการโปรด / ประวัติ / ข้อความ / ค้นหา — การสแกนทั้งระบบครอบคลุม**สตริง UI กว่า ~1,650 รายการ** บวกเนื้อหาแบบไดนามิก (ชื่อเรื่อง ชื่อผู้แต่ง จำนวนการกระทำ)
- **สองเอนจิน หนึ่งสวิตช์.** *ในตัว* (ค่าเริ่มต้น) ใช้ endpoint ฟรี **Index-Translate-35B-A3B** อย่างเป็นทางการของ bilibili — ไม่ต้องตั้งค่าอะไรเลย *API ของตัวเอง* ใช้พฤติกรรมเดิม: ชี้ไปที่ endpoint `/chat/completions` ที่รองรับ OpenAI ใดก็ได้ ด้วย base URL / key / โมเดลของคุณเอง ฟีเจอร์สรุปวิดีโอด้วย AI กับฟีเจอร์แปลด้วย AI ยังคงมี endpoint และการตั้งค่า**อิสระต่อกันโดยสิ้นเชิง** ทั้งคู่อยู่ในหน้า "**ฟีเจอร์ AI**" หน้าเดียว
- **รายการภาษาเดียว ใช้ร่วมทั้งสองเอนจิน.** รายการภาษาปลายทางไม่ได้แยกตามเอนจิน — เสนอรายการเดียวกันไม่ว่าจะเลือกเอนจินใด โดยรวม**151 ภาษา**ของโมเดลทางการของ bilibili เข้ากับ**อีก 6 ภาษาที่ไม่ครอบคลุม** — จีนตัวเต็ม อู๋ตัวย่อและตัวเต็ม ฮกเกี้ยนแบบแผ่นดินใหญ่และไต้หวัน และจ้วง ภาษาย่อยตามภูมิภาคและชุดตัวเขียนคงอยู่เป็น**รายการแยก**แทนที่จะกลืนรวมกัน — อาหรับโมร็อกโก / อียิปต์ / นัจดี / ลีแวนต์ เป็นตัวเลือกของตัวเองแต่ละภาษา เช่นเดียวกับเซอร์เบียนอักษรซีริลลิกกับละติน อุซเบก และอูรดู
- **ซื่อตรงเรื่องความครอบคลุม.** ภาษาที่อยู่ในรายการทางการได้รับการรองรับโดยโมเดลของ bilibili ส่วนภาษาที่อยู่นอกรายการ — จีนตัวเต็ม อู๋ตัวย่อและตัวเต็ม ฮกเกี้ยนแบบแผ่นดินใหญ่และไต้หวัน และจ้วง — ยังปรากฏในรายการพร้อมทำเครื่องหมายกำกับไว้ คุณจึงเห็นได้ทันทีว่าผลลัพธ์ที่ดีกว่าอาจต้องใช้โมเดลของคุณเอง
- **แปลครั้งเดียว แล้วคงตัว.** สตริงต้นทางแต่ละรายการถูกแปล**เพียงครั้งเดียว**; ผลลัพธ์ถูกบันทึกไว้ในเครื่องและ**ไม่ถูกแปลใหม่**เมื่อคุณเปิดหน้าจอนั้นอีกครั้ง — หลักการเดียวกับไคลเอนต์ทางการ เพื่อการแปลที่เสถียรและคาดเดาได้
- **ปุ่มสลับ ต้นฉบับ ⇄ คำแปล รายความคิดเห็น** (ไอคอนเล็ก ไม่ใช่คำภาษาจีน) `@mentions / [emoji] / #topics# / links` ถูกคงไว้เป็นโทเคน และ**ความคิดเห็นที่มีไฮเปอร์ลิงก์ก็ยังแปลได้โดยลิงก์กดได้เหมือนเดิม**
- **การแปลดัมมากุ (弹幕)** — สวิตช์แยกในแถวควบคุมขวาบนของตัวเล่น **ปิดไว้เป็นค่าเริ่มต้น** และต้องกดยืนยันผ่านกล่องที่ข้อความของมันเองก็ถูกแปลด้วย เมื่อเปิดใช้ ดัมมากุที่อยู่หน้าตำแหน่งเล่นจะถูกแปลล่วงหน้าเป็น**ชุดละ ~15 วินาที** (การเลื่อนไปตรงกลางจัดการอย่างถูกต้อง ไม่ใช่เริ่มนับจากต้น) การแปลจึงพร้อมก่อนข้อความเลื่อนเข้ามาถึงจอในส่วนใหญ่
- **สวิตช์โหมดคิด** (`enable_thinking`) สำหรับสมดุลคุณภาพกับความเร็ว พร้อมปุ่ม"**ทดสอบการแปล**"และ**ล้างแคช**ในหน้าการตั้งค่า
- **สลับภาษาไว**: คำขอแบบแบตช์ที่มี concurrency จำกัดบนแคชถาวร; การสลับภาษาจะบังคับสร้างหน้าจอปัจจุบันใหม่หนึ่งครั้ง คุณจึงไม่ต้องจ้องข้อความที่ยังไม่แปล การปิดการแปลด้วย AI จะคืนค่า UI ทั้งหมดเป็นข้อความต้นฉบับและไม่ส่งคำขอเลย
- **ขั้นตอนต้อนรับการเปิดครั้งแรก.** ครั้งแรกที่เปิดแอป กล่องโต้ตอบภาษาอังกฤษจะเสนอให้เปิดการแปล การตอบรับจะเปิดการแปล เลือกโมเดลในตัว เปิดหน้าการตั้งค่า AI และถามทันทีว่าคุณต้องการภาษาใด — ผู้ใช้ใหม่จึงไปจากติดตั้งจนถึงแอปที่แปลแล้วในสองแตะ
- **เล่นได้ทั่วโลก.** PiliBabel เลือก edge ต่างประเทศ (**Akamai** ระดับโลก, `mirror*ov`, `cn-hk-eq-bcache`) ที่ `playurl` แบบกำหนดเส้นทางตามภูมิศาสตร์ของ bilibili เสนออยู่แล้ว แทนที่จะตรึงคุณไว้กับโหนดแผ่นดินใหญ่ (Aliyun/Shenzhen) — ผู้ใช้นอกจีนแผ่นดินใหญ่จึงไม่ค้างอีกต่อไป ("เสียงเล่นต่อ วิดีโอกลับค้าง") คุณยังตรึง CDN เองได้ในการตั้งค่า
- **หน้า "ธีมและสี" สไตล์ Material You.** โหมดสว่าง / มืด / ตามระบบ เลือกจาก**การ์ดพรีวิวสดสามใบ** — แต่ละใบวาดมินิเอเจอร์ของอินเทอร์เฟซจริงด้วยสีที่โหมดนั้นจะใช้จริง (การ์ด "ตามระบบ" แบ่งเฉียงครึ่ง สว่างซ้อนบนมืด) ใต้การ์ดลงมา: **สีไดนามิก** (ดึงจากวอลเปเปอร์ของระบบเมื่ออุปกรณ์รองรับ) **โหมดมืดคอนทราสต์สูง** (พื้นผิวดำสนิท เบากับตายามค่ำคืน) และ**ตัวเล่นโหมดมืดเสมอ** ฝั่งสียังเก็บพาเลตต์ FlexScheme ครบถ้วน — **สีตั้งต้น 19 สี** บวก"**สไตล์พาเลตต์**"แยกต่างหาก ที่กำหนดว่าสีของคอนเทนเนอร์ทุกสีจะถูกอนุพันธ์จากสีตั้งต้นอย่างไร โดยไม่ขึ้นกับสีตั้งต้นที่คุณเลือก
- **LXGW WenKai มาพร้อมกับแอป.** ฟอนต์ **LXGW WenKai (霞鹜文楷)** ถูก**รวมมาในแอปและตั้งเป็นค่าเริ่มต้น** — ฟอนต์จีนโทนอบอุ่น อ่านง่ายยิ่ง ที่คุณมีทันทีที่ติดตั้ง แทนที่จะต้องออกหาเองในตัวเลือกฟอนต์ ใช้กับทั้งอินเทอร์เฟซ*และ*ดัมมากุ คุณยังสลับกลับไปใช้ฟอนต์ระบบ เลือกฟอนต์ระบบใดก็ได้ที่ติดตั้งไว้ หรือนำเข้า `.ttf` / `.otf` / `.ttc` ของคุณเอง; ฟอนต์ที่เคยเลือกไว้ชัดเจนก่อนหน้าจะถูกเก็บไว้ข้ามการอัปเกรด น้ำหนักและขนาดยังปรับได้เหมือนเดิม

## การแคชเสียงออฟไลน์และดาวน์โหลดลงโฟลเดอร์ในเครื่อง (เฉพาะ PiliBabel)

สองความสามารถที่ PiliNara / PiliPlus ต้นน้ำไม่มี — มุ่งให้คุณเป็นเจ้าของสื่อของคุณแบบออฟไลน์ได้จริงทั้งคู่

### แคชเสียง (แคชออฟไลน์เฉพาะเสียง)

- **แทร็กเสียง ไม่ใช่วิดีโอ.** มีรายการ *แคชเสียง* อยู่ใต้ *แคชวิดีโอ* ในเมนูหน้าวิดีโอ พร้อมปุ่มแคชเสียงเฉพาะทางในแถบด้านบนของหน้าฟังวิดีโอ
- **เลือกระดับคุณภาพ.** Hi-Res แบบไร้สูญเสีย, Dolby Atmos, 192K, 132K หรือ 64K — รายการพรีเซ็ตเดียวกับที่ตัวเลือกคุณภาพวิดีโอใช้
- **คอนเทนเนอร์ดั้งเดิม ไม่มีการแปลงรหัส.** ไฟล์ถูกเขียนลงตรงตามที่ CDN ส่งมา: `m4a`, `mp3`, `flac`, `wav`, `aac` หรือ `ogg`
- **เป็นโมดูลของตัวเอง.** หน้าแคชแยกเป็น *วิดีโอที่แคช* / *เสียงที่แคช* และจำได้ว่าครั้งก่อนคุณอยู่โมดูลใด
- แตะรายการเสียงที่แคชไว้จะเปิดตัวเล่นเสียงทันที; ลบได้ทีละรายการหรือทีละหลายรายการ

### ดาวน์โหลดลงโฟลเดอร์ในเครื่อง

- **เป็นรายการเมนูของตัวเอง.** *ดาวน์โหลดลงโฟลเดอร์ในเครื่อง* เป็นรายการแยกในเมนูหน้าวิดีโอ อยู่ใต้ *แคชเสียง* — การแคชในแอปกับการบันทึกลงโฟลเดอร์เป็นสองการกระทำคนละอย่าง
- **ดาวน์โหลดวิดีโอหรือดาวน์โหลดเสียง.** รายการจะถามก่อนว่าต้องการแบบใด แล้วจึงถามระดับคุณภาพ (ตัวเลือกคุณภาพวิดีโอ / คุณภาพเสียง)
- **โฟลเดอร์ของคุณ กติกาของคุณ.** เลือกโฟลเดอร์ใดก็ได้ผ่านตัวจัดการไฟล์ของระบบ (Settings → *ดาวน์โหลดลงโฟลเดอร์ในเครื่อง*) และเปลี่ยนหรือล้างได้เมื่อไรก็ได้ ถ้ายังไม่เคยเลือกเลย ตัวเลือกโฟลเดอร์จะเปิดขึ้นทันที
- **ไฟล์เล่นได้ทันที.** วิดีโอถูกดึงมาเป็นสตรีมเดียวที่ผสมเสียงภาพรวมกันแล้ว (`fnval=1`) สิ่งที่ลงมาอยู่บนดิสก์จึงเป็น MP4 ธรรมดาที่ส่งต่อให้ตัวเล่นใดก็ได้ — ไม่มีสตรีมแยกที่ต้องมาเย็บต่อภายหลัง
- **เสียงคงรูปแบบดั้งเดิม** — ไม่มีการแปลงรหัส เหมือนแคชในแอปทุกประการ
- ไฟล์ถูกตั้งชื่อตามชื่อวิดีโอและไม่เขียนทับไฟล์ที่ดาวน์โหลดไว้เดิม

## เอนจินการแปลทั้งสอง

| | ในตัว (ค่าเริ่มต้น) | API ของตัวเอง |
|---|---|---|
| โมเดล | **Index-Translate-35B-A3B** ทางการของ bilibili | อะไรก็ได้ที่รองรับ OpenAI |
| Endpoint | `index-translate.bilibili.com/v1` | base URL ของคุณ |
| API key | **ไม่ต้องใช้** | ของคุณ |
| ค่าใช้จ่าย | ฟรี | ตามอัตราที่ผู้ให้บริการของคุณเรียกเก็บ |
| คำขอ | สตริงเดียวต่อคำขอ | แบบแบตช์ (≤ 16 ต่อคำขอ) |
| ภาษาเพิ่มเติม | — | ทุกภาษาที่โมเดลของคุณรู้จัก |

**ทำไมเอนจินในตัวจึงส่งทีละรายการ.** Index-Translate เป็น*ผู้เชี่ยวชาญเฉพาะทางการแปล* และแบบแผนการเรียกใช้ที่ผู้พัฒนาเขียนไว้คือเทมเพลตรายการเดียว ("แปลข้อความต่อไปนี้เป็นภาษา X แล้วแสดงเฉพาะคำแปล") PiliBabel จึงส่งสตริงเดียวต่อคำขอบนเอนจินนี้ แทนพรอมต์แบบรายการเลขลำดับ/JSON array ที่ใช้กับการตั้งค่า API ของตัวเอง endpoint นี้เป็นบริการฟรี การเสี่ยงกับผลลัพธ์แบบแบตช์จึงไม่มีอะไรให้ได้เปรียบ — นี่คือการแลกเปลี่ยนอย่างตั้งใจ ยอมเพิ่มคำขออีกเล็กน้อยเพื่อลดช่องทางพลาดลงได้มาก

**อัปเกรดจาก 0.3.x.** การตั้งค่า API ของคุณเอง — base URL, key และโมเดล — **ถูกคงไว้ตามที่คุณตั้งไว้ทุกประการ** การเลือกเอนจินแค่ตั้งค่าเริ่มต้นเป็นโมเดลในตัว รอบแรกหลังอัปเกรดคุณจึงอยู่บนโมเดลฟรีของ bilibili; ให้เปิด *Settings → AI → ฟีเจอร์ AI → เอนจินการแปล* แล้วสลับกลับเป็น *API ของตัวเอง* เพื่อกลับสู่ค่าเดิมของคุณทันที

## การแปลอินเทอร์เฟซด้วย AI ทำงานอย่างไร (เชิงเทคนิค)

repository นี้**ไม่มีชั้นทรัพยากร i18n / ARB** — สตริง UI เป็นภาษาจีนที่ฝังค่าไว้ตรงๆ แทนที่จะเขียน widget ใหม่ทุกตัว PiliBabel เติมชั้นการแปลบางๆ ซ้อนลงไป:

1. **ตัวห่อหุ้มการค้นหาระดับโลก.** `lib/services/ui_translate/` เปิดเผยฟังก์ชันระดับบนสุด `uiTx(String src)` ข้อความ widget ที่เดิมเคยเป็น `Text('中文')` กลายเป็น `Text(uiTx('中文'))` มีการรัน **codemod** แบบสคริปต์ทั่วทั้งโปรเจกต์ (`tool/ui_translate_*.py`) — ราว **223 ไฟล์ / ~1,650+ สตริง** — โดยตัดคีย์เวิร์ด `const` ที่ใช้ไม่ได้แล้วทิ้งโดยอัตโนมัติเมื่อจำเป็น (รวมถึง generic อย่าง `const X<T>(...)` และชื่อแบบมีจุดอย่าง `const Positioned.fill(...)` และแปลงการประกาศ list/map แบบ `static const` เป็น `static final`)
2. **แกนกลาง `GetxService`** (`ui_translate_service.dart`):
   - แคช **ต้นทาง → คำแปล** แบบถาวร (อิง GetStorage) สตริงทุกรายการจึงแปลครั้งเดียวแล้วใช้ซ้ำได้ตลอดไป;
   - `tx()` อ่าน `RxInt revision` ก่อน แล้วจึงตัดสินใจ: ถ้าปิดอยู่ → คืนของเดิม; ถ้าภาษาปลายทางคือ**จีนตัวย่อ (`zh-CN`)** ให้คืนของเดิมโดยไม่ต้องยิงคำขอ API (เนื้อหาต้นทางของ Bilibili ส่วนใหญ่ท่วมท้นเป็นจีนตัวย่อ) ภาษาปลายทางอื่นทุกภาษา — รวมถึงจีนตัวเต็ม กวางตุ้ง อู๋/เซี่ยงไฮ้ และฮกเกี้ยน/หมิ่นหนาน — ต้องผ่านเอนจินที่ตั้งไว้; การเป็นสมาชิกตระกูลภาษาจีนเพียงอย่างเดียวไม่ได้ทำให้ข้ามการแปล จากนั้นเสิร์ฟจากแคชหรือ**เข้าคิว**;
   - สตริงในคิวถูก flush โดย**กลุ่ม worker** แบบ**apply ทีละส่วนต่อ chunk** (chunk ที่กลับมาแต่ละก้อนจะเพิ่ม `revision` ให้ข้อความค่อยๆ อัปเดต) และผลลัพธ์ถูก**เก็บถาวร** (แบบ throttle) ขนาดแบตช์และ concurrency ตามเอนจิน: **1 ต่อคำขอ**บนโมเดลในตัว **≤ 16 โดยมี ≤ 10 รายการกำลังบิน** บน API ของคุณเอง
3. **การหาค่าเอนจิน.** `TranslateProvider` (`builtin` / `custom`) ตัดสินว่า transport จะใช้ URL, key และโมเดลใด; นอกเหนือจากนั้นเอนจินทั้งสองใช้เส้นทางโค้ดร่วมกันเส้นทางเดียวและรายการภาษาเดียวกัน การสลับเอนจินจึงเป็นการตั้งค่าเดียว และไม่เคยเป็นชุดฟีเจอร์ที่ต่างกัน
4. **transport** ใช้ซ้ำช่องทาง**สตรีมมิ่ง**ที่ตรวจสอบแล้วเดียวกับสรุปวิดีโอด้วย AI — `AiChatService.streamChat` → `{base}/chat/completions` โดย `stream: true` (ใช้ได้กับ gateway ที่รองรับเฉพาะสตรีมมิ่ง) — โดยขยายให้การแปลใช้ `apiUrl` / `apiKey` / `model` **ของตัวเอง**และแฟลก `enable_thinking` ได้ การเปลี่ยนแปลงนี้**ใช้ย้อนหลังได้** สรุปวิดีโอจึงยังทำงานเหมือนเดิม
5. **ประโยคที่ฝังค่าตัวแปร** ใช้ `uiTxP(template, args)`: ประโยคเต็มที่มี `{0}`/`{1}` จะถูกแปลเป็นคีย์เสถียรคีย์เดียว (พรอมต์ขอให้โมเดลคงตัวแทนไว้) จากนั้นจึงแทนค่ากลับเข้าไป — สตริงแบบ `"共 {0} 条"` จึงแปลได้โดยส่วนที่เป็นค่าพลวัตไม่เพี้ยน
6. **ตารางภาษา** (`app_language.dart`): `AppLanguage` แต่ละภาษาบรรจุชื่อเรียกตนเองสำหรับแสดงผล สตริงพรอมต์ `toModel` ที่เข้ารหัสกติกาชุดตัวเขียน/ภูมิภาค และแฟลกว่ารายการทางการของ bilibili ครอบคลุมภาษานั้นหรือไม่ กติกาชุดตัวเขียน (จีนตัวย่อกับตัวเต็ม และคำสั่งความสอดคล้องของภาษาถิ่น) ไปถึงโมเดลได้ผ่านพรอมต์เท่านั้น และรอบการทำ normalize แบบกำหนดค่านิ่งฝั่งไคลเอนต์จะแก้ glyph ที่หลุดออกมาภายหลัง
7. **ความคิดเห็น** ไหลผ่าน `uiTxComment(text, id)` โดยคง `@ / [emoji] / #topic# / link` เป็นโทเคนเดิมๆ; rich-text span ที่บรรจุลิงก์ถูกแปลโดยยังเก็บตัวจับลิงก์เอาไว้ และชุด id รายความคิดเห็นขับเคลื่อนปุ่มสลับ ต้นฉบับ ⇄ คำแปล
8. **ดัมมากุ** (`danmaku/view.dart`): เมื่อสวิตช์เปิดอยู่ position listener จะไล่ช่วง `[playhead, playhead + 15s]` ทีละวินาที และอุ่น `uiTx()` บนเนื้อหาของดัมมากุแต่ละรายการ ทำให้รายการถูกแปลก่อนถึงจอ; การเปิดใช้จะล้าง canvas แล้ววาดใหม่ทันที
9. **คีย์พื้นที่จัดเก็บ**: `uiTranslate{Enabled,Provider,Lang,Model,ApiUrl,ApiKey,Thinking,Cache,Onboarded}`. **UI การตั้งค่า**: หน้า "ฟีเจอร์ AI" ระดับบนสุดหน้าเดียว (`lib/pages/setting/ui_translate/`) พร้อมบล็อกอิสระสำหรับสรุปวิดีโอด้วย AI และการแปลด้วย AI

**CDN ทั่วโลก (`VideoUtils.getCdnUrl`).** URL ของสตรีมถูกเซ็นกำกับไว้ และการเขียน host ของ URL ใหม่จะทำให้ถูกปฏิเสธด้วย 403 — การเล่นจึงไม่เขียน host ใหม่เป็นอันขาด PiliBabel คืน URL แบบ geo-route ที่ bilibili มอบให้ตาม IP ของไคลเอนต์ และเมื่อรายการผู้สมัครมี edge ต่างประเทศ (`*.akamaized.net`, `mirror(cos|ali|hw)ov`, `cn-hk-eq-bcache`) อยู่แล้ว ตัวนั้นจะถูกเลือกก่อน ส่วนการดาวน์โหลดซึ่งเปลี่ยน host ได้อย่างปลอดภัย ก็ยิ่งเลือก edge Akamai ระดับโลกเป็นพิเศษ และหมุนไปยังผู้สมัครที่เซ็นแล้วรายการถัดไปเมื่อเส้นค้างหรือปฏิเสธการ resume ลิงก์ P2P `/v/resource` แบบดิบยังถอยกลับไปใช้รีเลย์เดิมเพื่อเลี่ยง 404

**การประนีประนอมของการออกแบบ / ข้อจำกัดที่ทราบ.** เนื่องจากสตริงถูกห่อในที่เดิมแทนที่จะถูกดึงออกมาเป็นทรัพยากร พารามิเตอร์สตริงที่ไม่ใช่ `Text` อีกจำนวนหนึ่งและ rich-text span บางส่วนยังคงถูกเติมเข้าไปทีละส่วน สตริงที่ทำหน้าที่**คีย์เชิงตรรกะ** (เปรียบเทียบด้วย `==`, ใช้เป็นชื่อแท็บอย่าง `简介` หรือป้าย enum ที่ใช้ใน switch) ถูกตั้งใจ**ไม่**ห่อพร้อมกันทั้งหมด เพื่อไม่ให้พฤติกรรมพัง การแปลดัมมากุเป็นความพยายามเต็มกำลังบน canvas ที่เลื่อนไปเรื่อยๆ — ในดัมมากุหนาแน่นระดับสุดขีด คุณอาจเห็นของเดิมแวบหนึ่งก่อนคำแปลจะมาถึง การแปลต้องใช้เครือข่าย; ถ้าไม่มีเครือข่าย ภาษาปลายทางที่ไม่ใช่จีนก็จะไม่มีผล endpoint ในตัวเป็นบริการสาธารณะฟรีที่ bilibili ดูแล — หากถูกจำกัดอัตราหรือใช้งานไม่ได้ แอปจะบอกคุณ และคุณก็สลับไปใช้ API ของตัวเองได้

## บันทึกฟีเจอร์ที่สืบทอดมา (จาก PiliNara / PiliPlus)

ทุกอย่างด้านล่างนี้สืบทอดมาจาก PiliNara (และโดยสืบต่อจาก PiliPlus); PiliBabel เติมชั้นการแปลด้วย AI ซ้อนขึ้นไป

**UI และการปรับให้เข้ากับแพลตฟอร์ม**
- [x] เปลี่ยนชื่อแอปตามแพลตฟอร์มเพื่อให้หลายไคลเอนต์อยู่ร่วมกันได้ (PiliBabel ติดตั้งควบคู่ PiliNara ได้)
- [x] แก้การเรนเดอร์ Flutter ใต้หน้าต่างเล็กของ Xiaomi HyperOS ([#161086](https://github.com/flutter/flutter/issues/161086), ทาง [venera#467](https://github.com/venera-app/venera/pull/467)); แอนิเมชันย้อนกลับแบบทำนายล่วงหน้าบน Android
- [x] ปรับลำดับ/จำนวนการ์ด "ของฉัน" ได้เอง; ส่วนพรีวิวการ์ดประวัติและส่วน "ดูภายหลัง"
- [x] สลับแถบข้างอัตโนมัติด้วยความกว้างทริกเกอร์ที่ตั้งได้; คัดลอกรูปภาพจากกดค้าง / คลิกขวา; รีเฟรชสไตล์ MD3E ครั้งใหญ่

**ระบบฟอนต์** — พูลนำเข้ารวมเดียวพร้อมการตัดซ้ำด้วย content-hash ฟอนต์ดัมมากุรวมเข้าพูลเดียวกัน `loadFontFromList` รองรับ ttc และชื่อครอบครัวแบบ hash ที่เป็น ASCII ล้วน

**การเล่น หน้าต่างเล็ก และคุณภาพ** — หน้าต่างเล็กในแอป (ลาก, ปรับขนาด, ข้าม SponsorBlock, PIP ระบบอัตโนมัติ, แถบช่วยเหลือตัวเองระหว่างไลฟ์), เล่นเสียงหลายทางพร้อมกัน, ระดับเสียงในแอปสูงสุด 200%, โดเมน CDN วิดีโอแบบกำหนดเองพร้อมเลือกโหนดภูมิภาคด้วยการทดสอบ latency, คุณภาพเริ่มต้นคนละค่าสำหรับครึ่งจอ/เต็มจอ, ล็อกความเร็วเมื่อปัดขึ้น, ควบคุมด้วยคีย์บอร์ดบนแท็บเล็ต, timestamp ของ SuperChat ในไลฟ์, heartbeat ไลฟ์เพื่อความผูกพันแฟนคลับ

**ซับไทเติล, AI และออฟไลน์** — ซับไทเติลสองภาษาพร้อมการจัดสไตล์ซับรองแยกอิสระ, การวิเคราะห์ซับไทเติลด้วย AI (endpoint ที่รองรับ OpenAI แบบกำหนดเอง, กระโดดตาม timestamp, เทมเพลต, บันทึกบทสนทนาถาวร, ทางเลือกสำรองแบบนุ่มนวลเมื่อไม่มีซับ), ส่งออก WEBVTT/SRT, มุมมองคู่ของแคชออฟไลน์พร้อมจัดการโฟลเดอร์และคงอยู่ของเมทาดาทา, ส่งออกดาวน์โหลดไปยังโฟลเดอร์ Download สาธารณะ (Android)

**ดัมมากุและการบล็อก** — การสเกลดัมมากุที่รวมกันแบบปรับปรุง (สไตล์ [Pakku.js](https://github.com/xmcp/pakku.js)), การบล็อกด้วย regex เชิงภาพแบบบนลิสต์พร้อมนำเข้า/ส่งออก, การข้ามแบบเข้าในช่วงของ SponsorBlock, แถบความคืบหน้าพลังงานสูงแบบเคอร์เนลเกาส์เซียน

**การกรองระบบแนะนำ / ไดนามิก / ความคิดเห็น** — คีย์เวิร์ดชื่อเรื่อง/UP/ช่อง, ความยาว, จำนวนผู้เล่น, อัตราไลก์, ยกเว้น UP ที่ติดตาม, กรองเนื้อหาไม่ได้รับอนุญาต/เก็บเงินเท่านั้น, ไวท์ลิสต์ร่วม, ไดนามิกการค้า/ไม่ได้รับอนุญาต, ยกเว้นความคิดเห็นของ UP เองและความคิดเห็นที่ปักหมุด, โหมดฟีดรวม App+Web

**ไดนามิก การค้นหา และข้อมูลผู้ใช้** — โน้ตกำกับเองสำหรับ UP, โน้ตแทนชื่อเล่นใน 13 ช่องชื่อ, การเรียงความคิดเห็นซ้อนแบบอิสระ, ตัวกรองค้นหาคีย์เวิร์ดภายในเครื่อง, กระโดดลิงก์ย่อ b23.tv, ป้ายเก็บเงินเท่านั้น, สวิตช์ซ่อนเหตุผลการแนะนำ, การแสดง XP จากการโยนเหรียญ

**การปรับปรุงไลฟ์** — แผงสวมเหรียญแฟนคลับ, ทอดภาพ DLNA ที่เลือก HLS ก่อน, การแสดงเวลา SuperChat, แถบควบคุมล่างของหน้าต่างเล็กสำหรับช่วยเหลือตัวเอง

**การเชื่อมต่อระบบและเดสก์ท็อป** — SMTC บน Windows, MPRIS บน Linux (`audio_service_mpris`), การจัดการ audio-focus ที่เขียนใหม่

## ข้อปฏิเสธความรับผิดชอบ

PiliBabel เป็นโปรเจกต์ส่วนตัวที่ทำจากความสนใจ จัดทำขึ้น**เพื่อการเรียนรู้และทดสอบเท่านั้น**; โปรดลบภายใน**24 ชั่วโมง**หลังดาวน์โหลด

- PiliBabel เป็นไคลเอนต์**บุคคลที่สามที่ไม่เป็นทางการ** และ**ไม่มีความเกี่ยวข้อง ได้รับการรับรอง หรือได้รับการสนับสนุนจาก bilibili**
- API ทั้งหมดรวบรวมจาก endpoint สาธารณะที่เป็นทางการ; **ไม่มีเนื้อหาแบบแคร็ก สิทธิ์เกินควร หรือหลบกำแพงการชำระเงิน**
- **การแปลด้วย AI ทำงานบน endpoint ของโมเดลบุคคลที่สาม.** โดยค่าเริ่มต้นคือบริการ Index-Translate สาธารณะฟรีของ bilibili เอง; หากคุณสลับไปใช้ API ของตัวเอง ก็คือ endpoint ที่คุณกำหนด คุณภาพการแปลและความถูกต้องตามกฎเกณฑ์เป็นความรับผิดชอบของผู้ใช้และผู้ให้บริการโมเดลที่เลือก โปรเจกต์นี้**ไม่ได้โฮสต์โมเดลและไม่มี API key ใดๆ**
- เคารพลิขสิทธิ์และข้อกำหนดการใช้บริการของ bilibili โปรดใช้อย่างรับผิดชอบ

ด้วยความเคารพต่อผู้เขียนดั้งเดิมและต้นน้ำในความทุ่มเทเพื่อโอเพนซอร์ส:
- [guozhigq/pilipala](https://github.com/guozhigq/pilipala)
- [orz12/PiliPalaX](https://github.com/orz12/PiliPalaX)
- [bggRGjQaUbCoE/PiliPlus](https://github.com/bggRGjQaUbCoE/PiliPlus)
- [Starfallan/PiliNara](https://github.com/Starfallan/PiliNara) — โปรเจกต์แม่ที่ PiliBabel แตกกิ่งมาโดยตรง
- [bilibili/Index-Translate](https://github.com/bilibili/Index-Translate) — ตระกูลโมเดลแปลภาษาโอเพนซอร์สที่เอนจินในตัวเรียกใช้

หากเนื้อหาใดละเมิดสิทธิ์ของคุณ โปรดติดต่อเราเพื่อขอถอดออก
